# Architecture

Kodex is a browser-based workspace built around an external Codex app-server. Its design keeps the browser thin, the gateway authoritative for shared product state, and app-server authoritative for native Codex state.

## Components

| Component | Responsibility |
| --- | --- |
| React PWA | Renders projects, threads, timelines, approvals, terminals, settings, and app surfaces. Holds only browser-local interaction state where possible. |
| Rust gateway | Supervises app-server, exposes HTTP/SSE/WebSocket APIs, brokers approvals, projects app-server state, and owns local capabilities. |
| Codex app-server | Runs Codex sessions and owns durable transcripts, ordinary queues, native organization/settings and Codex account state. |
| SQLite | Stores promotion transfers, generated-app grants, read markers, automation schedules/run correlation, notifications and diagnostic events. Native queue payloads/order, projects, pins/order, thread settings and approvals are not persisted here. |
| Host integrations | Provide PTY terminal sessions, supported local-file previews, uploads and static frontend serving. |

## State ownership

Shared state must survive reloads, reconnects, and multiple browser tabs. Kodex therefore keeps shared lifecycle decisions in the gateway or upstream app-server instead of deriving them from one browser's event stream.

- App-server owns native project roots, metadata, order and thread membership, pinned membership and member order, descendant relationships and input capabilities, durable transcript history, Codex session lifecycle, effective thread settings and native approval requests. Project roots organize chats; they neither grant filesystem permissions nor change existing chat working directories.
- Gateway mirrors native approvals in connection-scoped memory and projects canonical thread state.
- App-server owns ordinary queued input, order and dispatch. The gateway owns narrow promotion-transfer recovery, read state, automation schedules/run correlation, notifications and generated-app grants.
- The browser may own drafts, focus, open dialogs, scroll position, and other per-tab presentation state.

Selecting an already-visible desktop pane activates its Dockview group without reopening the panel content, preserving the timeline’s current reading position. Hidden tabs use native panel focus to reveal their content. This focus and scroll behavior is local to each browser tab. Thread tabs reuse the sidebar running spinner and unread completion pulse, with running taking precedence. They project shared thread summaries and fall back to the mounted pane’s canonical status when a chat is outside the loaded sidebar pages; they do not keep a separate unread state.

After a native user item completes, `thread.summary_changed` invalidates sidebar metadata even for chats absent from the current browser list. The pinned paginated runtime has persisted the first input and preview at this point; thread creation and input acknowledgments are too early. Clients cancel stale sidebar reads, refill native summaries, and update pane titles from those summaries. Summary/name invalidations also replace a pane snapshot already in flight; captured-read reconciliation preserves names changed during that read while allowing later native reads to clear them. The signal is globally delivered and replayable, contains no title or membership state, and performs no native RPC in serial notification ingestion. Reload/reconnect reads use the same native list. There is no loaded-thread overlay, title generator, preview ledger, or polling loop.

Editable panes load and reconnect through the canonical attach command: native `thread/resume` with `excludeTurns: true` and a descending, full-item initial page of 50 turns. The gateway reverses that page once and uses its `nextCursor` for older history; the resume-level backwards cursor includes its anchor and is not an older-page continuation. Live SSE updates form a temporary projection over the native page. There is no separate browser attach effect, loaded-thread scan, disposition response or prose-based browser snapshot retry loop. Initial pane setup and actual SSE opens can each request a refill; canceled StrictMode reads do not become authoritative browser snapshots, although cancellation does not prove that an already dispatched native RPC did not execute. Native reads expose failures directly; Kodex does not infer transient rollout failures or retry them from message text.

The pinned native runtime reconstructs active resume items with temporary `item-N` IDs, which differ from persisted and live IDs. Active rejoins therefore read one additional native full-item page and merge current live state using native identity; idle resumes use their initial page directly. No alias table or text/client-ID deduplication is introduced. The native page limit bounds turns, not items within a turn. Read-state reconciliation uses a separate bounded terminal-header page; completion-count scans and the unused full-history walker are removed.

Canonical timeline activity groups span empty reasoning/plans, hook prompts and unsupported native bookkeeping such as `subAgentActivity`. Those items remain in the projection for diagnostics; they do not end a command/tool group. User and assistant messages (including empty placeholders), turn boundaries, visible reasoning/plans, review/compaction markers, errors and generated images retain their boundaries. Grouping is recomputed from current native content, so reasoning that becomes visible splits the group through the normal canonical patch/snapshot path. Keep the gateway grouping visibility rules aligned with frontend presentation when adding renderers; browser tabs do not independently regroup commands. Command-count increases use a local 150ms transform/opacity roll of the number only, replacing rapid updates rather than queuing animations. Initial loads, decreases and reduced-motion users receive the current count immediately; assistive technology receives the complete current summary once.

Transport cursors resume SSE; canonical payload revisions order the browser projection. A complete snapshot also establishes an ephemeral coverage revision: a newer lifecycle/partial patch alone does not prove that earlier text was included. Late partial data above that coverage requests the existing canonical refill instead of being appended twice or silently discarded. Pure reduction records an unresolved refill intent; the shared queue hook requests recovery once after React commits that intent and projection revision. Complete snapshots clear the intent. Unchanged renders and failed reads do not retry; a genuinely newer projection during a held repair requires a fresh read so the older reply cannot leave recovery unresolved. Once a complete snapshot covers old data, another copy does not request a refill. Queued delta prefixes are checked before concatenation; batching preserves canonical payload order and the maximum transport cursor. There is no per-row ledger or retry worker. Live operational events use the fixed replay-completion cutoff, so a later publisher cannot hide a delayed queue/config/read invalidation; reconnect and lag recovery retain the maximum observed cursor and canonical snapshots.

Projection mutations allocate their SQL cursor while holding the existing view write lock, then apply and capture the result under that same lock. Full/history snapshots therefore cannot claim coverage of an allocated but unfinished mutation. This boundary covers native item/turn/status/reset, accepted input and native/generated-app approvals; it adds no lock, counter or durable projection. Only local SQL runs under it, with native reads and other side effects outside. Stale reads preserve current overlap rows, turn metadata and lifecycle, including completion and reset-window cases. Current native reads own the turns they actually return; retained cached turns cannot borrow an unrelated older page's freshness. Head reads can retire temporary compaction markers while keeping omitted live rows. Missing native start metadata can enrich a known turn, but optional turn-start timestamps no longer decide snapshot staleness.

Compaction checks current native metadata and rejects observed active work without loading transcript history. A per-chat request lock serializes compaction requests through acknowledgment; native events own the resulting live state. There is no persisted execution-status mirror or synthetic busy state after acknowledgment. Native compact has no expected-turn precondition and can abort work at execution: simultaneous Send/Steer or native queue dispatch can race the metadata check. This is an observed-busy guard, not atomic exclusion of every native writer.

App surfaces persist their cached document, active/archived lifecycle, revision, bridge token, provenance and scoped grants. Sending an app message leaves the artifact active and supports repeated interactions. Working/error feedback belongs to the current browser bridge request; there is no one-shot submitted artifact state or submission-history column set.

History-only reads remain available for first-visit existence checks and the read-only subagent observer without activating queued work. A fresh loaded shell may reject resume before persistence. Only the exact native missing-rollout code/message for that thread permits an independent history read, which must prove the chat exists; unknown IDs and other resume errors are not turned into empty views. Archived chats and unloaded internal children can reject native resume. The observer remains available, and Kodex does not introduce silent unarchive or parent-activation fallback.

Native `thread/reverted` excludes its boundary turn and all later conversation history. Native execution stops and reloads the shortened thread while retaining settings/subscriptions; the response precedes the notification and contains no hydrated turns. On that notification, Kodex clears canonical live/history rows, the pending-input projection, turn bookkeeping and cursors, including an empty projection for an unseen chat. A per-thread reset revision in memory rejects older bootstrap/page/reconciliation replies before merging; an already stale HTTP read returns conflict before merging its canonical snapshot. Revisions are captured before native calls. Accepted input remains successful, but a late acknowledgment cannot reconstruct a pre-revert pending row. There is no gateway transcript replacement, ID ledger, file rollback or new browser revert action.

The canonical empty full snapshot is sent before the existing refill signal. SSE delivers that signal independently of the transcript high-water cursor because it supplies no transcript data; an interleaved broadcast cannot suppress a required native read. The high-water cursor never rewinds, and ordinary transcript events must still be newer. Full snapshots flush ordered browser batches immediately; editable and observer readers cancel obsolete requests, including older pages, so a slow or failed refill cannot leave removed rows visible. An old cursor submitted after reset follows the existing fresh-head reset-window path. Reconnect refills from native history when the notification was missed. Unsent drafts and independent app artifacts remain intact. History reads do not import app resources; successful live native calls can create separate gateway artifacts that conversation revert does not roll back. No notification-ingestion lock is held across native MCP calls.

Push preview generation reads native thread metadata and one descending item page scoped to the delivery's turn. It does not activate the thread, hydrate full conversation history or substitute another turn's answer. A missing turn ID, empty retained page or page without usable assistant text produces generic notification text. Native item pages preserve native turn/item identity and ordering; response scope errors and malformed required preview fields remain errors handled by the existing bounded delivery retries. Notification eligibility still comes from source, per-thread preference and foreground presence, independently of read receipts. Shared read state now uses native terminal IDs, an explicit seen ID and a gateway revision. A bounded descending header read supplies the completion head; a single unconfirmed live witness prevents a lagging native projection from replacing it with older history. Completion ingestion invalidates without awaiting native RPCs. Ordinary reads reconcile with a revision fence; ambiguous history stays unknown. The badge reads the complete eligible nonarchived native inventory, with at most four concurrent head queries and a separate membership fence. This is convergence across native reads, not a cross-RPC atomic snapshot. Push carries optional diagnostic badge state, but the worker obtains the current aggregate before updating its badge. Delayed payload counts do not become browser authority.

## Interactive app ownership

Native successful completed calls supply widget discovery (`mcpAppUi`, then the native resource URI, then fresh result metadata). Kodex retains the iframe host, CSP/permissions, explicit grants and saved app artifacts because app-server does not provide a browser host or generated-surface storage. Reading current or older chat history never activates MCP discovery or resource reads. Saved surfaces survive gateway reopen independently of the canonical transcript.

Hosted `codex_apps` imports require a matching native resource `originCallId`. Native call/account context remains in provenance; grants come from the originating chat/server catalog and match its app and account. Tool bridges reject an iframe-selected different account and overwrite reserved routing metadata with that native context. Extra resource reads use the same account's native direct target because an originating call authorizes only its widget URI. Missing or ambiguous context does not select a global or no-auth account. Fresh regular MCP result widgets remain supported without hosted account provenance. Generated tool approvals compare exact optional arguments and metadata before dispatch.

App-surface events cancel stale reads and refill the authoritative gateway query. They do not assign an event payload into the browser cache; publication and replay can follow a newer snapshot. Stream reopen and foreground recovery refill all mounted surface queries. App-produced chat messages render only from canonical native pending/receipt state, avoiding duplicate optimistic rows while an HTTP acknowledgment is held.

## Transport and API

- JSON-RPC over stdio connects the gateway to `codex app-server`.
- HTTP exposes snapshots and commands to the web client.
- Server-Sent Events carry gateway events and selected-thread live projections.
- WebSocket carries interactive PTY terminal input, resizing, and output.

Native project notifications invalidate authoritative sidebar snapshots rather than patching a second project registry. Project deletion also refreshes open thread snapshots, because the native membership notification excludes archived threads. A lagged SSE stream emits its existing refresh signals and closes at its previous cursor. Reconnection replays operational invalidations, and the browser refills current native state.

Pinned uses app-server’s reserved native section internally, with no independent Kodex pin table. Public contracts expose pinned membership and ordered pages only; custom sections have no management routes, tools, UI or caches. Pinning preserves projects and working directories; unpinning clears membership without remembering a previous section. Normal project/chat reads include existing custom-section members. Native pin mutations have no notification in the pinned runtime, so successful gateway writes publish a global `thread.pins_updated` refill marker. Browser reconnect/foreground recovery cancels stale sidebar and open-detail reads before reading native state. Activity and unread badges do not reorder pinned chats.

Existing-chat settings are read from native session state. Picker edits submit only changed fields; native queue acceptance is not an applied settings snapshot. Applied notifications carry a gateway refill marker, so replay cannot overwrite a newer read with an old settings object. Reconnect and foreground checks cancel stale reads and refill active queries. Draft choices are creation data, including native config for reasoning effort. Fresh native chats cannot resume full settings before their first turn; the browser refills unavailable settings when the canonical turn-start event confirms that boundary.

Subagent discovery forwards bounded native descendant pages without a gateway graph, loaded-thread union or repair scan. These pages cover persisted spawn relationships; ordinary pages exclude archived descendants and do not discover ephemeral activity or forks. History-only reads do not load an unloaded child. Global `thread.subagents_changed` markers refill descendant queries; their direct changed-thread ID refreshes only the matching canonical pane. The browser preserves native true/false/null input capability rather than inferring permission from a role. The retained observer sidebar has no input or approval actions. The gateway rejects definite native input denial before queue admission, editing, deletion, starting or promotion; it never replaces denial with a custom queue fallback.

Native skill selection owns free-text parsing, ambiguity, disabled entries and stale paths. All input producers forward text and explicit selections without gateway catalog resolution or rejection. Catalog caching and invalidation remain for autocomplete and icon serving. Live and historical user-item content supplies selected name/path and UTF-8 spans; a pure display projection validates those ranges and converts them to UTF-16 offsets. No skill-metadata text/FIFO association, historical catalog enrichment or skill-mention tables remain. Browser-local selected drafts and decorative metadata survive a definite failed submission only while the originating draft is unchanged. Confirmed badges use native content and do not certify skill execution.

Existing-chat composer Send opts into `queueIfPending` and reads one current native queue row under the existing gateway input exclusion, then appends through native queue admission when work remains or calls native atomic start-or-steer otherwise. Other input callers retain direct native atomic start-or-steer and the original response shape. Browser queue hints do not route requests, and queued acknowledgments remove the temporary optimistic timeline row and refill authoritative queue state. The native queue can dispatch between calls; if its last row has already begun before the read, Send may steer it. No cross-RPC atomic guarantee, cached active-turn routing, gateway start reservation or steering retry is added. Failed queue reads never fall through to input, and uncertain admission is never automatically retried. Explicit turn-start utilities remain direct; queued input rejects execution overrides that native queue storage cannot retain. Definite cold-thread absence permits one native resume followed by the same submission and client ID; other rollout-load failures and unsupported steering are surfaced without a hidden queue fallback. Explicit Queue and retained producers share native admission. Stop resolves the authoritative current native turn through the gateway and preserves native queue pause; selected-row Start delegates to the native idle-only command. Queue edits preserve raw native input. Metadata-only queue refill markers invalidate authoritative queries, including on reconnect; browser rows do not reconstruct durable state from upserts/tombstones. Ordinary queues remain dormant after native restart until their chat is loaded.

Schema-validated native queue adapters and shared admission/promotion handlers serve composer, Control and automations. A probe fences the bounded item-free active-turn read before add; acknowledged rows bind to that original turn. Promotion consumes an epoch claim and rechecks it after asynchronous preflight and before native mutations. Terminal/reset/disconnect retire context synchronously. Missing context leaves the queue untouched. Only a promotion transfer stores recoverable input: durable deletion/steering phases use conditional writes, the fresh transfer ID correlates exact native receipts, and repeated commands never repeat native writes. Original queue client IDs can repeat and are provenance only. Restart publishes metadata-only uncertainty refills without ordinary chat activation; one original-turn item page can establish positive delivery evidence without a history walk. Native dispatch can accept before cleanup, so deletion/absence cannot establish non-delivery. Transfer event failures must not prevent independent canonical reset/receipt ingestion or approval/completion cleanup. The browser exposes saved input and bounded reconciliation, without an automatic resend action.

Automation records persist immutable run targets and fresh client correlation before native writes, without copying queue payloads or execution options. Schedule claims coalesce missed intervals and allow one outstanding scheduled admission; explicit run-now is independent of cadence. Known acknowledged queue rows may reactivate only their own targets after restart. This accepts native dispatch semantics: native admission preceding failed row cleanup can cause an existing row to dispatch again. Lost add/start acknowledgments and ambiguous manual handoffs stay uncertain and never authorize automatic activation or resubmission. Exact native receipts settle run state; promotion receipts settle the matching producer before deleting transfer correlation. Dispatched means an acknowledged native turn start or a user-item receipt, not completed inference.

Control activates only explicitly named targets and queues once, honoring native pause. Spawn uses an existing audit intent and a minimal confirmed receipt under a per-key lock. An uncertain prior attempt cannot create another chat or retry admission. All Kodex row mutations share thread input locks; foreign writers in the private native home are unsupported. There is no ordinary queue table, global drainer or FIFO commitment recovery.

Native client-message IDs are opaque correlation data, preserved without display trimming in canonical user snapshots and live events. A browser generates one ID before each explicit Send attempt; gateway-originated submissions receive one when omitted. Gateway pending rows reconcile by turn and client ID, including native receipts preceding RPC acknowledgement. A native receipt inherits its matched provisional display position until a native item page supplies authoritative order. Browser optimistic rows reconcile by their submitted client ID; HTTP acceptance marks them sent without removing them ahead of canonical delivery, while a full native snapshot still governs whether acknowledged input exists. Foreign or ID-less equal-text messages do not consume pending input; canonical native rows remain keyed by native item ID, including repeated client IDs. No idempotency or committed delivery is inferred from an RPC acknowledgement.

Thread goals are native app-server state. The gateway forwards typed goal reads and sparse mutations without a goal table or continuation scheduler. Native `thread/goal/updated` and `thread/goal/cleared` notifications produce `thread.goal_changed` operational refill markers, including for model-originated changes. Browser goal queries cancel stale in-flight reads before refilling and recover on stream open and foreground checks; markers do not supply transcript rows or depend on transcript high-water cursors. Only unsaved modal drafts are browser-local. Goal mutation acknowledgments are followed by a native reread rather than installed over newer notifications. Objective and budget edits omit unchanged fields; explicit pause/resume changes status alone. The editor preserves drafts and asks for review when an edited field differs from the latest observed native value. The pinned goal API has no conditional-write version, so writes retain native last-writer semantics rather than adding a gateway revision store.


The generated OpenAPI document is the API contract. With the gateway running, use:

- `GET /docs` for interactive local API documentation.
- `GET /openapi.json` for the generated schema.

Frontend types are generated from that schema and committed at `apps/web/src/api/generated/schema.ts`. Kodex intentionally does not maintain a parallel handwritten route reference.

## Codex compatibility

The checked-in app-server schema under `apps/gateway/app-server-schema/<version>/json` defines the supported protocol. The gateway validates outbound client requests and the app-server `initialized` notification against it.

Thread start, resume, and fork use the exact 0.160.0 history parameters. Selected-thread detail uses bounded, full-item history pages so the browser can render rich completed history without owning a duplicate transcript. `/readyz` reports incompatibilities, and `/v1/capabilities` exposes the checked-in schema version plus the configured Codex CLI version when detectable.

Regenerate the schema whenever the supported Codex binary version changes; see [Development](development.md#generated-contracts).

## Security boundary

Kodex is designed for localhost or a trusted private network. It has no gateway authentication layer. Codex account login manages upstream Codex/OpenAI account state and does not restrict access to Kodex itself.

Anyone who can reach the gateway can potentially use its terminals, read supported local files, start configured MCP commands, and operate other host-level features with the gateway process's permissions. Review the full deployment considerations before binding beyond loopback: [Deployment security](deployment.md#security-model).

## Current scope

The current implementation includes the Rust gateway, React PWA, gateway-host PTY terminals, app surfaces, MCP management, the Kodex Control plugin, automations, and optional Web Push. The browser client is designed to be replaceable without changing the app-server or gateway ownership model.
